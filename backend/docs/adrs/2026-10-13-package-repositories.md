## Context

Packages were installed by pasting YAML. The official packages live in
`sinas-platform/packages`, but nothing in Sinas knew about it. A package
bundled with the platform (`way-of-working`) sat in the sinas repository
with no way to reach it from the console. Nothing told an operator that an
installed package had a newer version.

## Decision

**A package repository is a resource kind** (`packageRepositories`):
- a name, a URL, optional auth (a shared Secret's name), and `isActive`;
- managed in the console and REST, or declared in config;
- recorded in the change history (URL credentials redacted), with
  admin-only permissions.

Packages may not declare repositories: a package must not be able to add a
source of further packages. They are skipped like the other
environment-specific kinds.

**A repository is read through one `index.json`** (schema
`sinas.package-index/v1`). It lists each package's name, version, the path
of its `package.yaml` relative to the base URL, and the file's SHA-256.
- One request per refresh, so GitHub's unauthenticated API limits never
  come into it.
- It works on any static host.
- The index is generated by the repository, not by Sinas
  (`scripts/build_index.py` in sinas-platform/packages, with CI checking
  it is current).
- A GitHub repository URL is mapped to `raw.githubusercontent.com`, with
  `/tree/<branch>/<dir>` honoured; `main` is the default branch.

**Fetching** is server-side:
- HTTPS only (plain HTTP behind `PACKAGE_REPOSITORIES_ALLOW_HTTP`, for
  local development), also after redirects;
- no credentials in URLs;
- timeouts, and a size cap on every response;
- package paths must stay inside the repository.

**Refresh:**
- On create, on a URL or auth change, and on request.
- Hourly from the agent worker, for indexes older than
  `PACKAGE_REPOSITORY_REFRESH_HOURS` (6).
- A failure is stored on the row and the last good index kept.

**Installing from a repository** (`/packages/install` and `/preview` with
`repository` + `package`):
- fetches the file and refuses it unless it matches the index's SHA-256;
  on a mismatch the index is refreshed once first, since the repository
  may have published since;
- records `packages.source_repository`.

An update is an install of the newer version, through the existing upgrade
path: preview, variables, pruning what the new version dropped.

**Update status** (`latest_version`, `update_available`) comes from the
repository a package was installed from. For a package installed by
pasting YAML, it comes from the first repository offering a package of
that name. Versions compare semver-style; versions that don't parse make
no claim.

## Consequences

- Sinas needs outbound HTTPS to the repositories it is given.
- Nothing installs or updates without an operator choosing to.
- The official repository is one click away (`POST
  /package-repositories/official`), and is not added by default.

## Alternatives considered

- **Read the GitHub API to list package folders.** It is GitHub-only,
  rate-limited at 60 requests an hour unauthenticated, and needs one
  request per package.
- **Bundle packages in the sinas repository.** That ties package releases
  to Sinas releases, and splits official packages across two repositories.
- **Let packages declare repositories.** A package could then add a source
  of further packages; refused.
