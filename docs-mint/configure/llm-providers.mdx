---
title: "LLM Providers"
description: "API keys and model configuration"
---


LLM providers connect Sinas to language model APIs.

**Supported providers:**

| Type | Description |
|---|---|
| `openai` | OpenAI API (GPT-4, GPT-4o, o1, etc.) and OpenAI-compatible endpoints |
| `anthropic` | Anthropic API (Claude 3, Claude 4, etc.) |
| `mistral` | Mistral AI (Mistral Large, Pixtral, etc.) |
| `ollama` | Local models via Ollama |

**Key properties:**

| Property | Description |
|---|---|
| `name` | Unique provider name |
| `provider_type` | `openai`, `anthropic`, `mistral`, or `ollama` |
| `api_key` | API key (encrypted at rest, never returned in API responses) |
| `api_endpoint` | Custom endpoint URL (required for Ollama, useful for proxies) |
| `default_model` | Model used when agents don't specify one |
| `config` | Additional settings (e.g., `max_tokens`, `organization_id`) |
| `is_default` | Whether this is the system-wide default provider |
| `pricing` | Per-model prices for this provider's calls, in LiteLLM's per-token fields (see [Usage & Cost](/admin/usage-cost)) |
| `model_aliases` | Model name as called → the ratecard model it is priced as (e.g. an Azure deployment name → `gpt-4o`) |
| `discount` | Multiplier (0–1) on deployment-ratecard prices, for negotiated rates |
| `pricing_provider` | The LiteLLM provider family models are priced as (`pricingProvider` in YAML), for an OpenAI-compatible API of another provider. Unset: the provider type's own |

**OpenAI-compatible providers:**

Mistral, Groq, Together, DeepSeek or a LiteLLM proxy can be called through the `openai` type with their endpoint. For cost tracking, tell Sinas which provider's prices apply with `pricingProvider`; otherwise their models are priced as OpenAI's and mostly come out unpriced:

```yaml
llmProviders:
  - name: la-plateforme
    type: openai
    endpoint: https://api.mistral.ai/v1
    models: [mistral-large-latest]
    pricingProvider: mistral   # priced as mistral/<model> in the ratecard
```

In the console this is **Price models as** in the provider form's Pricing section. See [Usage & Cost](/admin/usage-cost#openai-compatible-providers) for how models are matched.

**Provider resolution for agents:**
1. Agent's explicit `llm_provider_id` if set
2. Agent's `model` field with the resolved provider
3. Provider's `default_model`
4. System default provider as final fallback

**Endpoints (admin only):**

```
POST   /api/v1/llm-providers             # Create provider
GET    /api/v1/llm-providers             # List providers
GET    /api/v1/llm-providers/{name}      # Get provider
PATCH  /api/v1/llm-providers/{id}        # Update provider
DELETE /api/v1/llm-providers/{id}        # Delete provider
```
